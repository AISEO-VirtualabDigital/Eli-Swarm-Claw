    84→## Why Digital Marketing Pro
    85→
    86→Most AI marketing tools generate isolated outputs — a campaign brief here, an email there. No canonical sequence, no shared state, no enforced structure. Result: inconsistent depth, missed dependencies, outputs that don't compound.
    87→
    88→**DM Pro runs every brand through the same 12 parts, producing the same files in the same order, with explicit dependency rules between them.** That's the whole product. Everything else — the 158 skills, 24 agents, May–June 2026 compliance updates, Cowork persistence — exists to make that 12-Part Flow ship cleanly for real agencies on real client work.
    89→
    90→| What this gives you that ad-hoc prompts don't | Why it matters |
    91→|---|---|
    92→| **Canonical 12-Part Strategy Flow** producing the Four Core Documents (61 explicit steps) | Every engagement looks the same, so handoffs work and quality is auditable |
    93→| **Two-Views Model** (v1 unbiased + v2 client-validated) | You never lose the original market view when the client pushes back |
    94→| **Decision Matrix** — maps validation responses to re-runs | Stops over-running (wasted hours) and under-running (broken strategy) |
    95→| **Living Project Instruction File** — single source of truth per engagement | All skills read it first; corrections propagate automatically |
    96→| **EU AI Act Article 50 readiness** built in | C2PA provenance signing, deepfake disclosure, final Article 50 Guidelines + Code of Practice (10 June 2026) in compliance |
    97→| **6-platform AEO/GEO audit** (incl. Google AI Mode) | The first marketing plugin to treat AI Mode as a distinct surface from AI Overviews |

   122→## Quick start
   123→
   124→### 1. Install on Claude Code (canonical)
   125→
   126→```bash
   127→/plugin marketplace add indranilbanerjee/neels-plugins
   128→/plugin install digital-marketing-pro@neels-plugins
   129→```
   130→
   131→`/plugin` commands work in **Claude Code** (CLI + IDE at [claude.com/code](https://claude.com/code)) and **Anthropic Cowork**. In the standard Claude chat app (browser `claude.ai` OR the installed Claude Desktop app) plugins still install and run, but management is via the **Plugins** UI button at the bottom of the chat — not via `/plugin` slash commands. See the [Updating](#updating) section for the recovery procedure if you accidentally try a slash command in the chat UI.
   132→
   133→### 2. Turn on auto-update (recommended)
   134→
   135→Third-party marketplaces have auto-update **OFF by default** in Claude Code — no banner tells you when a new version ships. Fix it once:
   136→
   137→Open `/plugin` → **Marketplaces** tab → find `neels-plugins` → toggle **Enable auto-update**. Done — future releases pull at session start; `/reload-plugins` applies mid-session without restart.
   138→
   139→### 3. Set up your first brand
   140→
   141→```
   142→/digital-marketing-pro:brand-setup
   143→```
   144→
   145→Interactive brand profiling — voice, audience, channels, industry, target jurisdictions, competitors, goals. Quick mode (5 questions) or full mode (17 questions). Optional: `/digital-marketing-pro:import-guidelines` to bulk-load existing brand guidelines, SOPs, or templates.

   328→## The 12-Part Engagement Methodology
   329→
   330→| Part | Name | Output |
   331→|------|------|--------|
   332→| 1 | Client Inputs | Stone vs Opinion intake (what client knows for certain vs what they believe) |
   333→| 2 | External Research | Unbiased market research (no client docs used) |
   334→| 3 | **Four Core Documents** | 61 explicit steps — Business & SBU (18), Segmentation (15), Brand Positioning (19), DMFlow (9) |
   335→| 4 | Competitive + Customer + Market | 4 unbiased analysis documents (4.1–4.4) |
   336→| 5 | **Client Validation Document** | The one true stop — client accepts/rejects/edits each finding |
   337→| 6 | Selective v2 Re-runs | Subset of Part 3 + Part 4 docs re-run per the Decision Matrix |
   338→| 7 | Preparation Documents | Internal operating layer (campaign architecture, KPI tree, content pillars, asset inventory, approval chains) |
   339→| 8 | **Growth Plan + Yearly Planner** | The flagship 11-section client-facing strategy + 12-month operational calendar |
   340→| 9 | Channel Strategy Fan-out | Up to 17 channel docs grouped into 7 families |
   341→| 10 | Execution Artefacts | Ad copy, post copy, headlines, CTAs |
   342→| 11 | AI Creative Instructions | Visual asset briefs with C2PA + EU Article 50 clauses |
   343→| 12 | **Continuous Improvement Loop** | Quarterly briefs feeding signals back into product/offering decisions |
   344→
   345→**Key architectural concepts:**
   346→- **Two-Views Model** — Every engagement carries v1 (unbiased market view) and v2 (client-validated view) after Part 5. Operating decisions reference v2; ideation references both. v1 is never deleted.
   347→- **Stone vs Opinion** — Every fact captured at intake is tagged with confidence. Stone = client knows for certain. Opinion = client believes (becomes a research question, not ground truth).
   348→- **Decision Matrix** — Maps client validation responses to which v1 documents need v2 re-runs. Prevents over- and under-re-running.
   349→- **Update-Back Rule** — Live operations surface corrections → source documents get versioned (v2.1, v2.2 …) → Living Project Instruction File propagates the change to all downstream skills.
   350→- **Living Project Instruction File** — Single source of truth per engagement. All skills read it first.
   351→
   352→15+ strategic-framework reference documents in `skills/context-engine/` support the methodology (Five Digital Markets, Channel Families, In-Market vs Out-Market, Multi-Dimensional Decision Framework, Unit Economics, Actionable Persona Format, B2B Decision-Making Unit, Three-Scenario Forecasting, 30/60/90-Day Framework, Reporting Cadence, Fixed vs Variable Budget, Competitor 3-Question Output, India Market Context, and more).

   462→## How the SEO skills chain together
   463→
   464→Most SEO work uses 3-5 skills in sequence rather than one mega-skill. The plugin is designed so that each skill produces numbered intermediate files (`01-...md`, `02-...md`, …, `PLAN.md`) under `${CLAUDE_PLUGIN_DATA}/{brand}/seo/{workflow}/{date}/` — downstream skills read those numbered files, not the endpoint, so you can re-run any single step without redoing the whole chain.

   477→5. /digital-marketing-pro:seo-plan                   ← DISPATCHER — reads all of the above, scores 4 pillars,
